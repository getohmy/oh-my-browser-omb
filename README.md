# Oh My Browser · OMB

### 让 AI Agent 看见并操作你已登录的真实网页

**读内部文档 · 等待异步内容 · 操作网页 · 验收代码修改**

[官网](https://omb.org.cn) · [安装指南](https://omb.org.cn/install) · [Chrome 商店 Lite](https://chromewebstore.google.com/detail/oh-my-browser-lite/akoahoncmadanincjkcgajofianmbbon) · [English](README.en.md)

</div>

> 你在浏览器里看得到，Agent 却只读到了登录页？
>
> 页面代码已经改好，Agent 说“测试通过”，你打开却发现布局仍然不对？
>
> 文档预览还在加载，Agent 就把空白结果当成了最终内容？

**OMB 把你正在使用的 Chrome 连接给本机 Agent。** Agent 可以在你的浏览器登录会话里读取页面、检查元素、执行操作、获取截图，并在内容异步加载时观察明确的就绪条件。

适合 **Codex、Claude Code 等 AI 编程工具的网页调试**，也适合 **办公、资料整理和跨网站工作**。普通网页无需接入 SDK；开发者可以额外接入 WebMCP 和诊断 SDK，提供业务上下文。

## 哪些时候值得用 OMB

| 你遇到的事情 | 可以交给 Agent 的工作 |
| --- | --- |
| 内部文档、OA、CRM 或订阅内容需要登录 | 在已有登录会话中读取你有权访问的页面，整理要点与结构化信息 |
| curl 失败、只拿到空壳或登录页 | 检查真实浏览器中的页面，确认内容、权限或加载状态 |
| React/Vue 页面、延迟列表、图片或文档预览 | 读取渲染结果，在同一个标签页观察目标内容是否就绪 |
| 修改了页面，但还没真正验收 | 检查 DOM、元素坐标、滚动区域和截图，再验证修改结果 |
| 页面点击失败、请求异常或状态不一致 | 结合页面状态、有限的运行错误及网络证据定位问题 |
| 网页表单、筛选和多步流程 | 先发现可操作元素，再在明确授权的范围内点击、填写和核查结果 |

简单公开事实仍可以用普通搜索。**需要你的登录身份、动态渲染结果或实际页面交互时，用 OMB。**

## 三步开始使用

### 1. 安装 CLI 和 Agent 集成

macOS / Linux 终端执行：

```bash
curl -fsSL https://api.omb.org.cn/install.sh | sh
```

全球接入入口：

```bash
curl -fsSL https://api-browser.getohmy.com/install.sh | sh
```

安装器下载 CLI、配置检测到的本机 Agent，并准备完整版 Chrome 扩展。按照终端提示完成账号连接和扩展加载。已有配置的更新按安装器提示处理。

### 2. 加载完整版扩展

1. 打开 Chrome 的 `chrome://extensions`。
2. 开启「开发者模式」，点击「加载已解压的扩展程序」。
3. 选择安装器显示的扩展目录，完成扩展登录。

macOS 默认目录为 `~/Downloads/oh-my-browser-extension`；其他环境以安装器输出为准。**命令下载了扩展文件后，仍需要在 Chrome 加载它；更新已加载的文件后，需要刷新该扩展。**

如果更喜欢商店安装，使用 [OMB Lite](https://chromewebstore.google.com/detail/oh-my-browser-lite/akoahoncmadanincjkcgajofianmbbon)。Lite 同样需要 CLI 和 Agent 连接；Full 与 Lite 选一个即可。

### 3. 在 Agent 里开始一个真实任务

```text
用 OMB 打开这个网址，读取我已登录页面里的内容，并整理重点：<网址>
```

在 Codex 中可以用 `/mcp` 查看 OMB 工具是否已连接。首次安装后若当前会话没有看到工具，按安装器提示重新加载连接或启动新会话。

## 直接发给 Agent 的任务示例

### 看已登录的文档

```text
用 OMB 读取这个内部文档，整理结论、待办和需要确认的问题。
如果页面只有外壳，检查正文是否在 iframe 中；不要把外壳当成全文。
网址：<网址>
```

### 获取稍后才出现的内容

```text
用 OMB 打开这个页面并保留标签页。目标是右侧的预览内容。
如果还在加载，观察加载提示消失，并确认预览图片已经解码或正文已经出现。
内容就绪后再总结；超时请说明实际观察到的状态。
网址：<网址>
```

### 验收修改后的网页

```text
用 OMB 验收本机页面，检查桌面和窄屏下的布局、滚动区域、按钮和错误状态。
结合 DOM 测量与截图确认，不要只根据构建成功或页面诊断健康下结论。
不要将浏览器切到前台影响我工作；遇到需要可见页面的能力限制时先说明。
网址：http://localhost:<端口>/<路径>
```

### 排查前端问题

```text
用 OMB 复现这个问题。先检查页面提供的 WebMCP 诊断工具，
再结合 DOM、请求和运行错误证据分析。
区分已观察到的事实和推测；修改后在同一页面复测，并清理测试标签页。
问题：<现象>
网址：<网址>
```

### 执行需要确认的网页操作

```text
用 OMB 找到这个表单，填写以下内容，先不要提交。
展示填写结果，等我确认后再提交。
网址：<网址>
填写内容：<内容>
```

## 为什么需要真实浏览器

| 获取方式 | 适合什么 | 需要注意什么 |
| --- | --- | --- |
| 普通搜索 / HTTP 获取 | 公开事实、静态网页、可直接访问的接口 | 通常没有你当前浏览器的登录会话；拿到 HTML 不代表内容已经渲染 |
| 独立自动化浏览器 | 隔离测试、可重复的自动化流程 | 通常需要单独准备账号和登录状态 |
| OMB 连接现有 Chrome | 你已登录的网站、动态页面、真实界面验收 | 使用当前浏览器的权限；部分能力取决于扩展版本、浏览器限制及页面是否可见 |

OMB 的价值是让 Agent 从“根据代码推测页面”走到“检查页面实际发生了什么”。它不会授予账号原本没有的访问权限，也不保证任何网站的访问挑战都能通过。

## Full 和 Lite 怎么选

**优先推荐 Full。** 两个版本共享网页读取与操作的基础实现，主要区别在安装方式、增强能力和并发容量。

| 能力 | Full（推荐） | Lite |
| --- | --- | --- |
| 安装方式 | 安装器准备扩展，在 Chrome 手动加载 | Chrome 应用商店安装 |
| 已登录页面读取 | 支持 | 支持 |
| 点击、填写、导航等基础操作 | 支持 | 支持 |
| 通用页面诊断 | 支持 | 支持 |
| 站点记忆 / 选择器缓存 | 支持 | 不支持 |
| 并发标签页操作 | 最多 8 个 | 1 个 |
| 更新方式 | 下载新版扩展后重新加载 | 商店审核发布后由 Chrome 更新 |

如果你主要做连续调试、多页面工作，选择 Full。如果你更重视商店安装流程，选择 Lite。**商店版本与服务器版本可能存在审核发布时间差。**

## 从页面问题到修复验收

```text
复现真实页面 → 收集证据 → 分析代码并修改 → 再次验证页面
```

以“页面有两条滚动条”为例，Agent 可以测量视口与文档高度、列出滚动容器、检查隐藏元素是否撑出布局，再用截图和实际滚动核查修改结果。

以“PDF 预览是空白”为例，Agent 应先确认加载过程：图片是否出现、是否完成解码、正文是否可见。首次读取没拿到内容，不应直接等同于页面故障。

**诊断工具报告健康，只说明其覆盖范围内没有发现相应错误；不代表布局正确、导入完整或业务流程成功。** 最终验收应结合任务的具体通过条件。

开发者可选接入 WebMCP / 诊断 SDK，把当前业务对象、明确的只读状态和诊断能力提供给 Agent。普通网页无需改代码即可使用 OMB。详见 [网页调试指南](https://omb.org.cn/guide/web-debugging)。

## OMB 提供哪些工具

这些工具由 Agent 调用，你通常只需要描述任务。

| 工具 | 用途 |
| --- | --- |
| `omb_read` | 打开并读取页面，或读取指定标签页 / iframe |
| `omb_page_watch` | 在已有标签页上观察异步内容与明确的就绪条件 |
| `omb_map` | 发现可交互元素及页面提供的 WebMCP 工具 |
| `omb_action` | 点击、填写、选择选项、执行脚本、截图及其他页面操作 |
| `omb_snapshot` | 获取可供后续操作定位的页面快照 |
| `omb_search` | 搜索网页 |
| `omb_status` | 查看 OMB 客户端及认证状态 |
| `omb_guide` | 获取具体工具参数、使用方式和恢复规则 |
| `omb_report` | 经用户授权，向 OMB 开发者提交工具问题或功能建议 |

连续操作从保留标签页开始，后续传入明确的 `tabId`。默认一次性读取会关闭 OMB 创建的标签页。Agent 的详细调用规则由安装的 Skill 和 `omb_guide` 提供。

## 常见问题

### 需要把网站密码发给 Agent 吗？

无需为了让 OMB 使用已有登录态而把目标网站密码发给 Agent。先在自己的 Chrome 中正常登录，再让 Agent 访问你有权访问的页面。读取结果和截图可能包含页面信息，应只让 Agent 查看任务所需内容。

### 支持本机 localhost 页面吗？

支持浏览器可访问的本机页面，适合前端开发和修改后的验收。先启动你的应用，再把完整 URL 发给 Agent。

### 内容在 iframe 里面怎么办？

让 Agent 保留标签页、发现实际 frame，再读取目标 frame。页面权限或 Chrome 限制可能阻止部分跨域内容访问，Agent 应明确报告该限制。

### 页面加载很慢，能知道什么时候完成吗？

使用 `omb_page_watch` 指定目标区域和就绪条件，例如正文出现、加载提示消失且图片完成解码。它是有时间预算的观察工具，返回初始状态、变化与最终状态；`ready` 只证明所声明的条件满足，不代表整个网站所有任务已完成。

### 会不会一直抢我的浏览器前台？

可在后台执行支持后台运行的任务。部分截图或原生浏览器交互存在可见性要求；应让 Agent 根据实际工具结果说明限制，不应把切换前台作为日常调试流程。

### 为什么安装完成后仍没看到 MCP 工具？

文件已安装、Agent 已注册和当前会话已加载工具是不同的状态。按安装器提示检查 Agent 连接；必要时重新加载宿主连接。可以先执行：

```bash
~/.omb/omb doctor
```

### 网页操作超时，要重试吗？

先让 Agent 核查目标页面的实际状态。超时后操作可能已生效，尤其是提交、创建、付款等动作，不应盲目重复执行。

### 支持哪些 Agent？

提供 Codex、Claude Code 等 Agent 的集成，并为多个客户端分发使用指引。不同宿主的工具发现和更新方式可能不同，安装器会展示当前检测和配置结果。具体支持情况以 [安装指南](https://omb.org.cn/install) 为准。

## 反馈问题

遇到可复现的 OMB 问题，可以告诉 Agent：

```text
请整理这次 OMB 问题并通过 omb_report 提交给开发者。
包含任务目标、最小复现步骤、预期与实际结果、具体错误、
相关调用返回的 request_id，以及实际核实的版本和发生时间。
缺失的信息明确写未知，不要猜测；不要提交密码、令牌或私人页面正文。
如果操作结果未知，不要为了复现而重复提交业务操作。
```

每次调用返回的 `request_id` 用于关联排查证据。反馈记录与原始调用的 ID 是不同的；提交反馈前需要用户授权。

也可以在 [本仓库 Issues](https://github.com/getohmy/oh-my-browser-omb/issues) 提交公开的问题与建议，请避免发布个人信息和私密内容。
